# README.md

## validate-domains.js

Скрипт для пакетной проверки доменных сущностей в формате `.ro` через GraphQL API. Он рекурсивно обходит указанный каталог, находит файлы `.ro`, проверяет, что в YAML указан `type: domain`, и отправляет содержимое файла в мутацию `checkRobject`. По результатам проверки выводится статус каждого домена и итоговая статистика.

---

## Что делает приложение

- Рекурсивно сканирует указанный каталог и ищет файлы с расширением `.ro`.
- Парсит YAML-содержимое файлов, включая «мягкий» режим разбора для нестандартных тегов и анкоров.
- Пропускает файлы, у которых `type` не равен `domain`.
- Для каждого домена отправляет GraphQL-запрос `checkRobject` с типом `DOMAIN`.
- Показывает результат:
    - ✅ домен валиден;
    - ❌ домен невалиден;
    - ⚠️ ошибка выполнения или парсинга.
- В интерактивном режиме может показать полную диагностику для невалидных доменов.
- В конце выводит статистику: сколько доменов проверено, валидных, невалидных, пропущенных и с ошибками.

- Node.js **18+** (используется глобальный `fetch`).

## Настройка

Настройки задаются через переменные окружения в файле `.env` в корне проекта.

### Обязательные переменные

| Переменная | Описание |
|---|---|
| `VALIDATE_URL` | URL GraphQL-эндпоинта для проверки доменов. Обязательна. |

### Авторизация

Можно использовать один из двух вариантов.

#### Вариант 1. Готовый токен

| Переменная | Описание |
|---|---|
| `AUTH_TOKEN` | Bearer-токен для авторизации. Если указан, вход по логину/паролю не выполняется. |

#### Вариант 2. Логин и пароль

Если `AUTH_TOKEN` не указан, обязательно должны быть заданы:

| Переменная | Описание |
|---|---|
| `LOGIN_URL` | URL GraphQL-эндпоинта для входа. |
| `LOGIN_USERNAME` | Имя пользователя. |
| `LOGIN_PASSWORD` | Пароль. |

Скрипт выполнит мутацию `login` и получит `accessToken`.

### Дополнительные переменные

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `TENANT_ID` | `00000000-0000-0000-0000-000000000000` | Идентификатор тенанта, передаётся в заголовке `x-tenant-id`. |
| `NODE_TLS_REJECT_UNAUTHORIZED` | `0` | `0` — отключить проверку TLS-сертификата, `1` — включить. По умолчанию в скрипте стоит `0`, это удобно для dev-среды, но небезопасно для production. |

### Пример `.env`

```env
VALIDATE_URL=https://example.com/graphql

# Вариант с готовым токеном
AUTH_TOKEN=eyJhbGciOi...

# Либо вариант с логином
# LOGIN_URL=https://example.com/graphql
# LOGIN_USERNAME=admin
# LOGIN_PASSWORD=secret

TENANT_ID=00000000-0000-0000-0000-000000000000
NODE_TLS_REJECT_UNAUTHORIZED=0
```

> ⚠️ В production рекомендуется использовать `NODE_TLS_REJECT_UNAUTHORIZED=1` и валидные сертификаты.

## Запуск

```bash
node validate-domains.js <каталог> [опции]
```

Пример:

```bash
node validate-domains.js ./domains
```

---

## Опции

| Опция | Описание |
|---|---|
| `--brief` | Компактный вывод. Для каждого проверенного домена выводится `✅ id`, `❌ id` или `⚠️ id`. Диагностика не выводится. |
| `--verbose`, `-v` | Полная диагностика выводится сразу для каждого невалидного домена. |
| `--help`, `-h` | Показать справку и выйти. |

Если опции не указаны, используется режим по умолчанию.

## Режимы работы

### Режим по умолчанию

```bash
node validate-domains.js ./domains
```

- Для валидного домена выводится:

  ```text
  ✅ domain-file.ro: OK
  ```

- Для невалидного домена выводится:

  ```text
  ❌ domain-file.ro: НЕВАЛИДЕН (диагностика будет доступна по запросу)
  ```

- После завершения скрипт спросит:

  ```text
  Показать полную диагностику для невалидных доменов? (y/N):
  ```

  Если ответить `y` или `yes`, будет показана подробная диагностика по каждому невалидному домену.

### Режим `--brief`

```bash
node validate-domains.js ./domains --brief
```

Выводится только идентификатор домена и статус:

```text
✅ my-domain
❌ broken-domain
⚠️ file-with-error
```

Где:

- `✅` — домен валиден;
- `❌` — домен невалиден;
- `⚠️` — ошибка парсинга или выполнения запроса.

Диагностика в этом режиме не выводится.

### Режим `--verbose` / `-v`

```bash
node validate-domains.js ./domains --verbose
```

Для каждого невалидного домена сразу выводится полная диагностика:

- severity;
- message;
- labels;
- primary;
- span start/end.

Интерактивный запрос в конце не задаётся.

## Формат файлов `.ro`

Скрипт обрабатывает только YAML-файлы с расширением `.ro`. Ожидается, что внутри есть поле `type`.

Пример домена:

```yaml
id: my-domain
type: domain
name: Мой домен
# ... остальные поля
```

Если `type` не равен `domain`, файл пропускается и попадает в статистику как `skippedNonDomain`.

Скрипт умеет разбирать YAML в несколько попыток:

1. Обычный `js-yaml`.
2. Мягкий режим с обработкой неизвестных тегов.
3. Очистка содержимого от тегов, анкоров и ссылок.

При этом на валидацию отправляется исходное содержимое файла, а не очищенное.

## Вывод и статистика

В конце работы выводится блок:

```text
============================================================
📊 ИТОГИ ВАЛИДАЦИИ
============================================================
Проверено доменов: 10
Успешно (isValid=true): 7
С ошибками (isValid=false): 2
Ошибки выполнения (⚠️): 1
Пропущено (не domain): 3
```

Поля:

- **Проверено доменов** — количество файлов с `type: domain`.
- **Успешно** — домены, для которых API вернул `isValid: true`.
- **С ошибками** — домены, для которых API вернул `isValid: false`.
- **Ошибки выполнения** — ошибки парсинга YAML, сетевые ошибки, HTTP-ошибки и т.п.
- **Пропущено (не domain)** — `.ro` файлы, у которых `type` не равен `domain`.

## Диагностика невалидных доменов

Для невалидного домена API может вернуть диагностику:

- `message` — сообщение;
- `severity` — важность;
- `labels` — метки с пояснениями;
- `primary` — основная ли метка;
- `span` — диапазон `start`–`end`.

Пример вывода:

```text
❌ broken-domain

   Диагностика:
   [1] Severity: ERROR
       Message: Некорректное поле ...
       Label: ...
       Span: 10 - 25
```

## Обработка ошибок

- Если не указан `VALIDATE_URL`, скрипт завершится с ошибкой.
- Если не указан `AUTH_TOKEN` и нет полных данных для логина, скрипт завершится с ошибкой.
- Если каталог не существует, скрипт завершится с ошибкой.
- Если API возвращает `401 Unauthorized`, выполнение прерывается с сообщением об ошибке авторизации.
- Ошибки парсинга YAML увеличивают счётчик `errors` и выводятся как `⚠️`.

---

## Ограничения

- Проверка выполняется последовательно, без параллельных запросов.
- Поддерживаются только файлы `.ro`.
- Токен не обновляется автоматически: если `AUTH_TOKEN` истёк, нужно получить новый.
- Скрипт не изменяет файлы, только читает и отправляет их содержимое на проверку.
